Who uses Letterbot?

Three profiles. Each is a real type of user — not a marketing persona. Each has a specific job to be done.

👤

Freelancers & sole traders

"I manage 20+ clients. A missed invoice or contract email costs me real money."

  • Priority alerts for invoices and contract deadlines
  • Obligation tracking — who promised what
  • Weekly digest with financial summary
  • Single Telegram chat as inbox dashboard
  • Works on a spare laptop — no extra hardware cost
💻

Developers & sysadmins

"I have 4 mailboxes. 800 unread. I want a self-hosted tool I can read the code of."

  • Multi-inbox routing: each account to its own Telegram chat
  • AGPL-3.0 — full source on GitHub, auditable
  • Local observability cockpit with SLA metrics
  • Works on Raspberry Pi (community-reported)
  • No Docker, no Kubernetes, no cloud subscription
🏢

Small businesses (Russia/CIS)

"We have B2B correspondence with contracts and invoices. We don't want it on US servers."

  • Data stays in Russia — no foreign cloud processing
  • GigaChat (Sber) as the AI — Russian LLM option
  • Works offline without LLM if needed
  • IMAP: Yandex, Mail.ru, corporate Exchange all supported
  • Telegram is already the team communication layer

The "old laptop" use case

One of the most satisfying Letterbot deployments.

Can a 2015 laptop become a useful local email server?
Yes — and this is one of the best Letterbot use cases. An Intel Celeron N4020 with 3 GB RAM runs Letterbot comfortably. An old laptop that would otherwise sit unused becomes a dedicated local email intelligence assistant: always on, always watching your inbox, always ready to send a Telegram notification when something important arrives.
The machine does not need a monitor connected. It just needs power, a network connection, and Windows 10/11. Set it up once, leave it running. Check email from your phone via Telegram.
What does a freelancer's daily workflow look like?
Morning: open Telegram, see the overnight digest — any invoices, contracts, or urgent requests. During the day: each important email arrives as a single Telegram message with the action needed. Evening: review the priority queue, snooze anything for tomorrow. No inbox needed. No email client open all day.
How do developers use the multi-inbox routing?
A typical setup: work email → #work-alerts Telegram group, personal email → private DM to self, GitHub notifications → #github-inbox channel, monitoring alerts → #ops channel. Four inboxes, four Telegram destinations, one Letterbot instance, one local SQLite database, zero cloud dependencies.
